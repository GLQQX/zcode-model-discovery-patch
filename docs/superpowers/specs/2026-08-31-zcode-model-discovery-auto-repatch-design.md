# ZCode 模型发现补丁自动恢复设计

## 目标

在 ZCode 自动更新替换 `resources/app.asar` 后，自动检测并重新应用“拉取模型、模型元数据补全、视觉模型识别和 CORS”补丁，同时保证新版结构不兼容时不破坏官方安装。

## 约束

- 不修改 ZCode 官方更新器。
- 不在补丁结构校验失败时覆盖官方 `app.asar`。
- 不依赖每次运行时访问 npm；部署时固定并安装 ASAR 处理依赖。
- 不强制结束用户正在运行的 ZCode。
- 每个官方版本只保存一份原始备份，并提供明确的恢复入口。

## 部署目录

补丁器安装到：

`%USERPROFILE%\.zcode-model-discovery-patch`

目录包含：

- `apply-patch.mjs`：补丁检测、解包、变换、验证、封包和安装逻辑。
- `payload/model-discovery.js`：版本化的模型发现实现。
- `patch-manifest.json`：补丁版本、必需锚点、变换规则和文件校验信息。
- `node_modules/@electron/asar` 及固定依赖：部署时安装，后续可离线运行。
- `state.json`：最后发现的官方哈希、最后成功补丁哈希、补丁版本和待处理状态。
- `logs/patcher.log`：兼容性失败和安装结果。
- `backups/<official-sha256>.asar`：每个官方版本的原始包。

## 检测机制

注册用户级计划任务 `ZCode Model Discovery Patch`：

- 用户登录时运行一次。
- 此后不再周期轮询；下一次用户登录时运行一次。
- 使用隐藏窗口运行，不弹出终端。

每次运行读取安装目录中的 `app.asar` 并计算 SHA-256：

1. 哈希等于已成功补丁后的哈希：直接退出。
2. 哈希等于已知官方哈希但上次因 ZCode 占用而未安装：重试安装。
3. 哈希为新值：按新官方版本处理。

## 补丁流程

1. 将当前 `app.asar` 复制到当前用户临时目录，所有操作都在临时目录完成。
2. 解包并定位实际渲染器 bundle，不依赖固定的哈希文件名：
   - 读取 `out/renderer/index.html` 的入口资源；
   - 在候选 JS 中查找模型供应商编辑组件的必需锚点；
   - 要求每个关键锚点只命中一次。
3. 应用版本化变换：
   - 添加“拉取模型”界面和状态；
   - 正确绑定 `modelProviderService`；
   - 写入当前 API 格式对应的 `kinds`；
   - 注入版本化的 `model-discovery.js`；
   - 在主进程中仅对模型发现相关响应补充 CORS。
4. 验证：
   - 每项必需变换均已应用且旧错误锚点消失；
   - 对修改后的 JavaScript 执行 `node --check`；
   - 重新封包后再次从 ASAR 读取关键文件并验证补丁标记；
   - 生成包的 SHA-256 与安装后的文件必须一致。
5. 首次遇到该官方哈希时，将原始包写入 `backups`。
6. 使用同目录临时文件加重命名方式替换 `app.asar`；若文件被占用，记录 `pending` 并由下一次计划任务重试。

## 不兼容处理

任何以下情况都视为新版不兼容：

- 找不到目标组件或主进程锚点；
- 关键锚点出现零次或多次；
- JavaScript 语法检查失败；
- 封包校验失败；
- 安装后哈希不一致。

发生不兼容时：

- 保留官方 `app.asar` 不变；
- 删除临时产物；
- 在日志中记录官方哈希、失败阶段和具体锚点；
- `state.json` 标记为 `incompatible`，同一官方哈希不重复进行高频失败尝试；补丁版本更新后允许重新尝试。

## 恢复

`apply-patch.mjs --restore`：

- 根据 `state.json` 找到当前官方版本对应备份；
- 验证备份哈希；
- 恢复官方 `app.asar`；
- 不删除其他版本备份。

卸载计划任务不会自动删除备份或恢复 ZCode，避免隐式覆盖用户选择。

## 测试

- 单元测试：锚点唯一性、幂等性、已补丁包跳过、未知版本不覆盖、状态迁移和备份选择。
- 集成测试：对当前官方 ASAR 解包、应用、语法校验、重封包和二次读取验证。
- 真实界面冒烟测试：启动带 CDP 的 ZCode，进入模型设置，点击“拉取模型”，确认 HTTP 200、模型写入、无错误边界，并在重启后确认持久化。
- 失败测试：删除或复制一个锚点，确认补丁器退出失败且原始安装哈希不变。

## 安全边界

- 补丁器只允许操作固定的 ZCode 安装路径和自己的 `%LOCALAPPDATA%` 目录。
- 所有待覆盖路径先解析为绝对路径并校验父目录。
- 不递归删除安装目录。
- API Key 不写入补丁日志或状态文件。
- 外部模型目录仅用于公开模型元数据，不发送 API Key 或供应商配置。
